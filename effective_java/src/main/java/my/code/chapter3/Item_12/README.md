## 📌 3.3 "Завжди перевизначайте toString()"

### 🧠 Головна ідея:
> toString() має повертати зрозумілий, інформативний, дружній для читача опис об'єкта.

Це допомагає:
- зручніше логувати,
- дебажити програми,
- краще тестувати,
- відображати дані у UI, REST API, CLI, тощо.

### 🔍 За замовчуванням:
Java-об'єкти наслідують toString() від Object, і воно виглядає приблизно так:
> User@4a54c0de

🤨 Без користі. Незрозуміло, що це за об'єкт, які в нього поля.


### ✅ Порада Джошуа Блоха:
> Завжди перевизначай toString(), якщо клас не є суто внутрішнім (він буде використовуватись зовні, або його логуватимуть).

### ✅ Як правильно реалізовувати toString()?
- Вказати важливу інформацію про стан об'єкта (поля).
- Наприклад: "User(name=Ivan, email=ivan@gmail.com)".
- Зручно реалізовувати через String.format(...), StringBuilder, або використати бібліотеки (Lombok, Apache Commons, ToStringBuilder).



## 3.3 Всегда перекрывайте toString (Item 12)

Всегда перекрывайте метод `toString` в каждом инстансированном классе, если только он не переопределен в суперклассе.

Предоставление хорошей реализации метода `toString` делает ваш класс гораздо более удобным в использовании, а
использующею его систему - более простой в отладке.

Чтобы представлять интерес на практике, метод `toString` должен возвращать всю полезную информацию, которая содержится в
объекте.

Документируйте логику вывода `toString`, если даже не стандартизируете формат вывода.

Предоставляйте программный доступ ко всей информации в значении, возвращаемом методом `toString`.
