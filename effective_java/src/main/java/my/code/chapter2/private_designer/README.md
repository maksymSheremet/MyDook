## 🔹 Пункт 4: "Забороняйте створення екземплярів за допомогою приватного конструктора"

### 🧠 Про що йдеться?

Цей пункт каже: якщо клас призначений лише для статичних методів або констант, його не треба створювати як обʼєкт.
Бо створення такого обʼєкта не має сенсу.

### 🔒 Як це зробити?

#### Треба зробити приватний конструктор:
```java
public class MathUtils {
  private MathUtils() {
    throw new AssertionError("Неможливо створити обʼєкт MathUtils");
  }

  public static int square(int x) {
    return x * x;
  }

  public static int cube(int x) {
    return x * x * x;
  }
}
```
Тепер неможливо зробити new MathUtils(), бо конструктор приватний.

## ✅ Навіщо?
- Клас виглядає логічно: лише static методи.
- Краще читається.
- Не дає антипатернів, типу new Utils().someMethod();
- Застосовується в java.lang.Math, Collections, Files, Objects і т.д.

## 2.4 Обеспечивайте неинстанцируемость с помощью закрытого конструктора (Item 4)

Это подходит для классов, который имеет только статистические методы и статистические поля (утильные классы).

Например:

- Группировка связанных методов над примитивами или массивами (`java.util.Arrays`)
- Группировка статистических методов и фабрики (`java.util.Collections`)
- Группировка методов в `final` - классе

```java
public class UtilityClass {
    private UtilityClass() {
        throw new AssertionError();
    }
}

```
