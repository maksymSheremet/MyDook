
## 📌 4.11: "Ограничивайтесь одним классом верхнего уровня на исходный файл"

### 📘 Про що це?
🔑 Головна ідея:
>У кожному .java файлі має бути не більше одного публічного класу верхнього рівня (тобто того, який не є вкладеним).

### 🛠 Просте пояснення:
В Java:
- Кожен публічний (public) клас має бути в окремому файлі, названому за іменем класу.
- Це робить код:
  - легше зрозумілим;
  - простішим для пошуку;
  - безпечнішим під час компіляції.

### ❗️ Що буде, якщо так не робити?
Якщо в одному .java файлі буде кілька класів верхнього рівня:
- тільки один із них може бути public;
- інші — будуть мати "пакетну" видимість (package-private);
- це плутає читача — незрозуміло, який клас основний;

❌ Поганий приклад: два класи у файлі Animals.java
```java
// Animals.java
public class Dog {
  public void bark() {
    System.out.println("Woof!");
  }
}

class Cat {
  public void meow() {
    System.out.println("Meow!");
  }
}
```
- Тут Dog — public, Cat — звичайний (package-private).
- Погано, бо файл має змішану відповідальність.

✅ Кращий варіант:
```java
Dog.java
public class Dog {
  public void bark() {
    System.out.println("Woof!");
  }
}
Cat.java
public class Cat {
  public void meow() {
    System.out.println("Meow!");
  }
}
```
- Тепер кожен клас в окремому файлі, все чисто й передбачувано.



### 📋 Чому це добре?
- Легко знайти потрібний клас (ім'я класу = ім'я файлу).
- Легше підтримувати великий проект.
- Менше шансів на неочевидні помилки.
- Відповідає стандартам Java.

### 🧠 Висновок:
| *Що краще робити*                  | *Чому*                           |
|------------------------------------|----------------------------------|
| Один клас верхнього рівня на файл  | Чистота, порядок, менше помилок  |




## 4.11 Ограничивайтесь одним классом верхнего уровня на исходный файл (Item 25)

Никогда не размещайте несколько классов верхнего уровня или интерфейсов в одни исходном файле. Это гарантирует, что не
будет нескольких определений одного класса во время компиляции.
