
## 📌 5.4: "Предпочитайте обобщенные типы"

### 📌 Головна ідея:
>Коли створюєш свої класи або методи, замість конкретних типів використовуй параметри типу (<T>). Це зробить код:
> - гнучкішим
> - безпечнішим
> - більш універсальним

### 🤔 Чому масиви неідеальні?
Усе просто: коли ти пишеш, наприклад, StackOfStrings, він буде працювати тільки з рядками. Якщо тобі треба StackOfInteger, доведеться писати новий клас.

➡️ Якщо ж написати узагальнений клас Stack<T>, він буде працювати з будь-яким типом, і компілятор гарантує типову безпеку (type-safety).

❌ Поганий приклад (без дженеріків):
```java
public class StringStack {
   private String[] elements = new String[10];
   private int size = 0;

   public void push(String item) {
      elements[size++] = item;
   }

   public String pop() {
      return elements[--size];
   }
}
```
➡️ Щоб зробити таку ж структуру для Integer, потрібно писати ще один клас. ❌

✅ Кращий варіант — обобщённый тип:
```java
public class Stack<T> {
   private Object[] elements = new Object[10];
   private int size = 0;

   public void push(T item) {
      elements[size++] = item;
   }

   @SuppressWarnings("unchecked")
   public T pop() {
      return (T) elements[--size];
   }
}
```
➡️ Тепер можна використовувати Stack<String>, Stack<Integer> або будь-який інший тип. ✅

### 🧠 Пояснення простими словами
 - Дженеріки дозволяють написати один клас/метод, який працює з будь-яким типом, але при цьому тип безпечний і перевіряється компілятором.
- Дженеріки роблять код менш дубльованим, зрозумілішим і надійним.


### 🧾 Висновок
| *Без дженеріків*           | *З дженеріками (<T>)*                  |
|----------------------------|----------------------------------------|
| Код дублюється             | Один універсальний код                 |
| Типова небезпека (casting) | Типова безпека                         |
| Неможливо перевірити тип   | Помилки ловляться на етапі компіляції  |
👉 Пиши узагальнені типи, якщо хочеш, щоб твій код був універсальний і безпечний.





## 5.4 Предпочитайте обобщенные типы (Item 29)

Обобщенные типы безопаснее и проще в использовании, чем типы, которые требует приведений в клиентском коде. При
разработке новых типов убедитесь, что они могут быть использованы без таких приведений.
