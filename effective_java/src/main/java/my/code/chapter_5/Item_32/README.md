
## 📌 5.7: "Аккуратно сочетайте обобщенные типы и переменное количество аргументов"

### 🔑 Головна ідея:
> Метод може приймати змінну кількість аргументів через ...,
> 
> але поєднання з дженеріками (<T>...) — небезпечне, якщо не бути обережним.

### 📦 Що таке varargs?
Це коли метод приймає будь-яку кількість параметрів:
```java
public void printAll(String... strings) {
    for (String s : strings)
        System.out.println(s);
}
```
📞 Можна викликати так:
```java
printAll("one", "two", "three");
```

### 🤯 У чому проблема з дженеріками + varargs?
❗ Дженеріки реалізуються через type erasure (стираються типи під час компіляції)

А varargs — це масив, тобто потенційно небезпечна ситуація:
```java
@SafeVarargs
public static <T> List<T> unsafeAddToList(T... elements) {
    List<T> list = new ArrayList<>();
    for (T element : elements) {
        list.add(element);
    }
    return list;
}
```
Якщо хтось передасть масив з сирих типів — може виникнути ClassCastException у runtime ❌

### 🧯 Як бути?
1. Уникай змінної кількості аргументів дженериків, якщо можеш.
2. Якщо впевнений, що це безпечне — помічай метод анотацією:
```java
@SafeVarargs
```
>Ця анотація каже компілятору: "Я знаю, що роблю. Це безпечно." ✔


### 🧠 Просте правило:
- Дженеріки + varargs = ⚠ можливо небезпечно
- Додавай @SafeVarargs, якщо:
  - метод final, static або private
  - ти впевнений, що не буде порушення типів

### 🧾 Висновок:
| Проблема                                                 | Рішення                                    |
| -------------------------------------------------------- | ------------------------------------------ |
| `T...` створює масив дженериків                          | може бути небезпечним                      |
| `varargs` + дженеріки = потенційний `ClassCastException` | обгорни в `@SafeVarargs` якщо **safe**     |
| Не можна анотувати **non-final** методи                  | Виняток: лише `private`, `static`, `final` |
👉 Використовуй @SafeVarargs, коли метод справді безпечний — і краще уникай необмеженої дженеричності без крайньої потреби.



## 5.7 Аккуратно сочетайте обобщенные типы и переменное количество аргументов (Item 32)

Следует помнить, что методы с переменным количеством аргументов и обобщенные типы взаимодействуют не очень хорошо,
потому что параметр переменной длины представляет собой утечку абстракции, построенную поверх массива, а правила типов
для массивов отличаются от правил для обобщенных типов.

Если метод вызывается с переменным числом параметров, выведение типов которых недоступно во время выполнения, компилятор
выдает предупреждение для такого вызова.

Опасно хранить значение в обобщенном массиве-параметре переменной длины.

```java
public class Dangerous {
    // Mixing generics and varargs can violate type safety!
    static void dangerous(List<String>... stringLists) {
        List<Integer> intList = List.of(42);
        Object[] objects = stringLists;
        objects[0] = intList; // Heap pollution
        String s = stringLists[0].get(0); // ClassCastException
    }
}

```

Но методы с переменным количеством параметров обобщенных или параметризованных типов могут быть весьма полезны на
практике, поэтому разработчики языка решили оставить эту несогласованность `Arrays.asList(T... a)`, `Collections.addAll(
Collection<? super T c, T... elements>)` и `EnumSet.of(E first, E... rest)`.

Обобщенный метод с переменным количеством аргументов безопасен, если:

1. Он ничего не сохраняет в массиве параметра переменной длины;
2. Он не делает массив (или его клон) видимым ненадежному коду.

Аннотация `@SafeVarargs` представляет собой обещание безопасности с точки зрения типов от автора метода. Используйте
`@SafeVarargs` с каждым методом с параметром переменной длины обобщенного или параметризованного типа, если гарантируете
безопасность.
