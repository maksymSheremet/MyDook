
## 📌 5.2: "Устраняйте предупреждение о непроверяемом коде"

### 🔍 Що таке непроверяемое предупреждение (unchecked warning)?
Це попередження компілятора Java, яке виникає тоді, коли він не може перевірити безпеку типів під час компіляції через особливості роботи з дженериками (generics) і type erasure (стирання типів).
```java
List<String> list = new ArrayList<>();
List raw = list; // сирий тип
raw.add(123);    // Java не може перевірити тип — буде unchecked warning
```

### 📌 Головна думка:
> Якщо ти бачиш unchecked warning, не ігноруй його. Зроби так, щоб він зник. Якщо зникнути не можна — поясни, що ти робиш, і свідомо придуши попередження через @SuppressWarnings("unchecked").

### 📉 Чому це важливо?
- unchecked warnings — це не помилка, але вони вказують, що в майбутньому твій код може "впасти" через помилку типу.
- Краще заздалегідь відрефакторити код або чітко обмежити ризик, ніж чекати сюрпризів під час виконання.

🧠 Приклад з поясненням
```java
public class Example {
  public static void main(String[] args) {
    List<String>[] array = new ArrayList[10]; // unchecked warning!
    array[0] = new ArrayList<>();
    array[0].add("Hello");

    List<Integer> wrong = new ArrayList<>();
    wrong.add(42);
    array[1] = (List) wrong; // небезпека!

    String s = array[1].get(0); // ClassCastException під час виконання
  }
}
```

### 🧾 Висновок:
- ⚠️ unchecked warning — це попередження, що Java не може гарантувати типову безпеку.
- ✅ Завжди намагайся усунути такі попередження.
- 🧠 Якщо повністю уникнути не можна — локалізуй ризик, задокументуй і використай @SuppressWarnings("unchecked").




## 5.2 Устраняйте предупреждение о непроверяемом коде (Item 27)

При использовании обобщенных элементов, можно столкнуться с предупреждением компилятора:

- о непроверяемом приведении
- о непроверяемом вызове метода
- о непроверяемом параметризованном типе с переменным количеством аргументов
- о непроверяемом преобразовании

Следует устранять все предупреждения о непроверяемом коде, какие можно устранить!

Если нельзя устранить предупреждения, но есть уверенность, что код, о котором предупреждает компилятор, безопасен, то
тогда(и только тогда!) можно скрыть предупреждения с помощью аннотации `@SupressWarnings("unchecked")`.

Всегда используйте аннотацию `@SupressWarnings` в наименьшей возможной области видимости.

Каждый раз при использовании `@SupressWarnings("unchecked")` нужно добавлять комментарий с пояснением, почему в данном
случае этот код безопасен.
