
## 📌 5.3: "Предпочитайте списки массивам"

### 📌 Головна ідея:
>У сучасній Java краще використовувати колекції (особливо List) замість масивів, бо:
> - вони безпечніші (працюють із дженеріками),
> - гнучкіші (змінюваний розмір),
> - легше працювати з ними у більшості сценаріїв.

### 🤔 Чому масиви неідеальні?
1. 🔒 Масиви мають фіксовану довжину:
```java
String[] array = new String[10];
```
→ не можна додати чи видалити елементи — лише перезаписати.
2. ⚠️ Масиви не підтримують дженеріки:
```java
List<String>[] listArray = new ArrayList[10]; // Warning: unchecked
```
3. 🧨 Проблема з "reifiable" типами (type erasure):
   - Java стирає параметри типів у generics під час компіляції. А масиви перевіряють типи під час виконання — виникає конфлікт.


### ✅ Чому краще List?
1. 🔄 Гнучкість:
   - Можна додавати, видаляти, фільтрувати, сортувати — без зайвої логіки.

2. 🛡 Безпечність:
   - Завдяки дженерікам компілятор перевіряє типи — помилки ловляться на етапі компіляції.

3. 📚 Великий набір зручних методів:
   - Методи add, remove, contains, sort і т.д.




### 🧠 Приклад:
❌ Поганий варіант з масивом:
```java
public class Utils {
    public static Object[] toArray(Object a, Object b) {
        return new Object[] {a, b};
    }
}
```
→ ти можеш передати будь-що, навіть числа, хоча хочеш рядки.
✅ Кращий варіант з List:
```java
public class Utils {
    public static <T> List<T> toList(T a, T b) {
        return List.of(a, b);
    }
}
```
→ тип безпечний: якщо T — це String, то помилка при передачі Integer.

### 🧾 Висновок
| *Масиви*                        | *List*                              |
|---------------------------------|-------------------------------------|
| Фіксована довжина               | Гнучкий розмір                      |
| Немає дженеріків                | Підтримує дженеріки                 |
| Можливі помилки під час runtime | Перевірка типів на етапі компіляції |
| Менше методів                   | Багато зручних методів              |
🔧 Висновок: якщо нема конкретної потреби в масиві (наприклад, інтеграція з нативним кодом або оптимізація по швидкості), краще використовувати List.


## 5.3 Предпочитайте списки массивам (Item 28)

Отличия массивов от списков:

1. Массивы **ковариантны** - если `Sub` является подтипом `Super`, то `Sub[]` является подтипом `Super[]`. Обобщенные
   типы **инвариантны** - для двух различных типов `Type1` и `Type2` тип `List<Type1>` не является ни подтипом,
   ни супертипом `List<Type2>`.

2. Массивы являются типами, доступными во время выполнения программы. Обобщенные типы, реализуются с использованием
   затирания, то есть тип доступен во время компиляции, но во время исполнения неизвестен.

С учетом данных отличий, массивы обеспечивают безопасность времени выполнения с точки зрения типов, но не безопасность
типов при компиляции, и наоборот.

```java
class Item27 {
    void method27() {
        // Fails at runtime
        Object[] objectArray = new Long[1];
        objectArray[0] = "I don't fit in"; // Throws ArrayStoreException

        // Won't compile
        List<Object> ol = new ArrayList<Long>(); // Incompatible types
        ol.add("I don't fit in");
    }
}

```

Из-за этих отличий нельзя перемешивать листы и массивы. Нельзя создавать подобные
элементы: `List<E>[]`, `new List<String>[]`, `new E[]`.
