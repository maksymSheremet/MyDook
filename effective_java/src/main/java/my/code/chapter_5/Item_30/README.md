
## 📌 5.5: "Предпочитайте обобщенные методы"

### 📌 Головна ідея:
>Коли функціональність залежить від типу даних, але сам клас не має бути узагальненим — використовуй дженерики прямо в методі.

Це називається generic method — узагальнений метод.

### 🤔 У чому різниця?
🔵 Узагальнений клас:
```java
public class Box<T> {
    private T value;
    public T get() { return value; }
}
```
➡️ Весь клас працює з типом T.

🟢 Узагальнений метод:
```java
public class Utils {
    public static <T> T getFirst(List<T> list) {
        return list.get(0);
    }
}
```
➡️ Метод узагальнений, але клас — звичайний.

### 🤓 Просте пояснення
- Якщо ти не хочеш робити цілий клас дженеріковим, але метод має працювати з різними типами 
  - — зроби узагальнений метод.
- Це гнучко, безпечніше, і зменшує дублювання коду.

### 🧾 Висновок
| Без generic method*               | *З generic method*            |
|-----------------------------------|-------------------------------|
| Потрібно кастити вручну           | Тип визначається автоматично  |
| Можливі помилки під час runtime   | Перевірка на рівні компіляції |
| Повторення коду для різних типів  | Один метод — багато типів     |
👉 Generic method = типобезпечна універсальна функція. Використовуй, якщо метод повинен працювати з будь-якими типами.




## 5.5 Предпочитайте обобщенные методы (Item 30)

Обобщенные методы, подобно обобщенным типам, безопаснее и проще в использовании, чем методы требующие от своих клиентов
использовать явные приведения входных параметров и возвращаемых значений.

Для метода сравнения объектов в коллекции, каждый объект должен быть сопоставим с любым другим её элементом. Этом можно
сделать с помощью рекурсивного ограничения `<E extends Comparable<E>>`.
